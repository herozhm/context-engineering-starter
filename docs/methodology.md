# 方法论:AI 时代的上下文工程(四层流水线)

## 核心认知

AI 编码的三大失效(静默失败、占位实现绕守卫、幻觉接口、盲目重试)共同根因是**上下文缺失或被稀释**。
解法不是换更强的模型,是上下文工程——本仓库就是这个理念的最小落地。

## 四层流水线

```
① 知识层  CLAUDE.md + .ai/agents/*   不变量、危险地图、回归清单、判据
② 执行层  skills/* + MCP             高频工程动作固化为确定性流程
③ 验证层  scripts/verify-changed 等   mock + 用例 + 实测(无输出≠通过)
④ 沉淀层  事故复盘 → 回写知识层        同一个坑不踩第二次
```

### ① 知识层:AI 的交通规则

- 全局约束常驻根上下文;任务域知识按需路由(4MB 全量塞不进,60KB 按需覆盖 1.5% 却够用)
- 四要素:不变量 / 危险地图 / 回归清单 / 判据
- 写作纪律:判据可执行、反例必写、真源指针化、事故驱动更新

### ② 执行层:把纪律变成确定性

- 没有 Skill 时,「提交要拆分」是文档里的一句话,AI 一半概率违反
- 封装成 Skill 后变成确定性流程——把纪律从「希望 AI 记得」变成「AI 不可能不记得」

### ③ 验证层:防静默失败

- 收尾三件套:mock(依赖没就绪先跑通)+ 用例(关键分支)+ 运行时实测(真实界面行为)
- 增量校验的 `executed` 防呆:检查器没跑成功时明确返回失败,而不是「无输出长得像通过」

### ④ 沉淀层:事故的出口是知识库

- 每次复盘的产出物之一是一条新约束,回写知识层
- 经验从「个人脑子里」变成「仓库里的结构化资产」——人走了,经验留下

## 通用性边界

机制(四层流水线、脚本、防呆)100% 通用;知识内容领域专属——
**框架可以开源共享,领域知识才是团队资产。** 这也是本仓库只含机制不含你业务知识的原因。
