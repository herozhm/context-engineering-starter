# 提交前校验流程

## 目标
提交前完成「增量校验 + 关键分支自查」,确保 AI 的产出经过验证而非「写完即完成」。

## 工作流

1. 运行增量校验:`node scripts/verify-changed.mjs`
   - 判据:输出「✅ 通过」才允许进入提交;输出「⚠ 没有任何检查器真正执行」时,**先修复检查环境,禁止跳过校验直接提交**
2. 对本次改动回答三个问题(自查):
   - 改动是否触碰危险地图命中的区域?(`.ai/danger-map.json`)
   - 是否存在「同一逻辑写两遍」的链路?若有,两处都改了吗?
   - 是否补了防御性处理(空值/边界),而不是假设字段一定有值?
3. 三个问题确认后,再生成提交

## 反例(历史事故,禁止重演)

- 检查器冷跑 OOM 输出 0 行,长得像通过——被误判为通过(这就是 executed 防呆存在的原因)
- 双链路只改一处,编译过、测试绿,另一入口静默失效
