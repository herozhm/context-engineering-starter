# 任务拆解(四步法)

## 目标
把需求拆成「每个都带验收判据、授权级别、依赖关系的可执行单元」。

## 工作流

### 第 1 步:需求理解确认
- 先**复述你对需求的理解**,等用户确认边界——模糊需求在这一步消灭
- 禁止:理解有歧义就直接开始拆

### 第 2 步:影响面分析
- 检查 `.ai/danger-map.json`,列出改动可能触碰的危险区
- 输出影响面草稿(改哪些文件/模块/系统、跨不跨链路),**请用户确认并补充 AI 不知道的隐含依赖**

### 第 3 步:任务分解
每个任务强制携带三件套,缺一不可:

- **验收判据**(可执行的验证动作;写不出判据 = 继续往下拆)
- **授权级别**(四维度判定:失败可见性 / 影响面 / 验证覆盖 / 是否契约;
  命中危险地图 → 最高 human-led)
- **依赖关系**(显式编号引用)

### 第 4 步:执行排序
- 串行走依赖链,无依赖的并行

## 反例(历史教训)
- 禁止把整个需求当成一个任务——大目标写不出验收判据,等于没拆
- 禁止跳过影响面确认直接拆——影响面漏了,后面全白干
